# HH Telegram Vacancy Bot

Telegram-бот для поиска вакансий на HH и отправки уведомлений подписчикам.

## Быстрый старт

1. Установите зависимости:
   - `npm install`
2. Создайте `.env` из примера:
   - скопируйте `.env.example` в `.env`
   - укажите `TELEGRAM_BOT_TOKEN`
   - укажите `ADMIN_CHAT_IDS` (например `123456789,987654321`)
3. Настройте параметры в `config/settings.json`.
4. Запустите бота:
   - dev: `npm run dev`
   - prod: `npm run build` и `npm start`

## Команды бота

- `/start` — подписка на уведомления.
- `/stop` — отписка от уведомлений.
- `/settings` — текущие настройки в читаемом виде (без показа admin id).
- `/filters` — все фильтры поиска одним сообщением.
- `/queries` — список поисковых фраз.
- `/keywords` — текущие ключевые слова включения/исключения.
- `/import` — бот включает режим ожидания и ждет JSON-файл или JSON-текст (только admin chat id).
- `/export` — выгрузка текущих настроек в JSON-файл (только admin chat id).

## Настройки

Все настройки лежат в `config/settings.json` и валидируются по `config/settings.schema.json`:

- `pollIntervalMinutes` — интервал опроса HH.
- `searchQueries` — массив поисковых запросов (синонимы вакансии).
- `requiredKeywords` — ключевые слова для включения: хотя бы одно должно встретиться в названии, навыках или описании вакансии.
- `excludedKeywords` — ключевые слова для исключения: ни одно не должно встретиться в названии или навыках.
- `hh` — параметры HH API.
- `telegram.messageDelayMs` — пауза между отправками.
- `ollama` — проверка релевантности локальной моделью (необязательный блок, см. ниже).
- `ADMIN_CHAT_IDS` в `.env` — chat id, которым разрешены `/import`, `/export`, `/clear_db` (через запятую).

Ключевое слово должно стоять в начале слова: `vue` найдёт `Vue3` и `Vue.js`, а `ios` не сработает на `Axios`.

## Проверка релевантности (Ollama)

Вакансии, прошедшие фильтр по ключевым словам, дополнительно оценивает локальная модель в [Ollama](https://ollama.com): в Telegram уходят только те, которые она сочла подходящими под профиль.

1. Установите Ollama и скачайте модель: `ollama pull gemma3:4b`.
2. В `config/settings.json` заполните блок `ollama`:
   - `enabled` — включить проверку;
   - `model` — имя модели в Ollama;
   - `profile` — описание обычным текстом, какие вакансии вам подходят и какие нет.
3. Если Ollama работает не на `http://127.0.0.1:11434`, укажите адрес в `OLLAMA_BASE_URL` в `.env`. Таймаут одного ответа модели (по умолчанию 120 с) меняется через `OLLAMA_TIMEOUT_MS`.

Модель оценивает роль и основной стек вакансии. Небольшие модели вроде `gemma3:4b` плохо учитывают другие условия из профиля (формат работы, опыт, город), а после правки профиля стоит проверить по dev-логам `[relevance]`, что вердикты не поехали.

Вердикты модели кэшируются в `data/app.db` и пересчитываются после смены `model` или `profile`. Если Ollama недоступна, непроверенные вакансии не отправляются и проверяются заново в следующем цикле.

## Запуск на GitHub Actions

Бот может работать без своего сервера: workflow [`.github/workflows/bot.yml`](.github/workflows/bot.yml) дважды в час собирает проект, поднимает Ollama с моделью из `config/settings.json` и выполняет один цикл опроса (`npm run start:once`). Второй workflow, [`ci.yml`](.github/workflows/ci.yml), проверяет типы и сборку при каждом пуше.

Настройка:

1. В репозитории откройте Settings → Secrets and variables → Actions и добавьте секреты `TELEGRAM_BOT_TOKEN` и `ADMIN_CHAT_IDS`. Пока токена нет, запуски по расписанию ничего не делают.
2. Первый запуск можно сделать вручную: Actions → Bot → Run workflow.
3. Напишите боту `/start` — команда обработается при следующем запуске.

Особенности такого режима:

- Команды бота обрабатываются только в начале очередного запуска, поэтому ответ приходит с задержкой до получаса и больше: GitHub нередко запускает расписание с опозданием.
- Подписчики и история отправленных вакансий (`data/`) хранятся в кэше GitHub Actions. Кэш удаляется, если к нему не обращались 7 дней; после этого бот начнёт с пустого состояния и нужно снова отправить `/start`.
- Настройки берутся из `config/settings.json` в репозитории. Изменения через `/import` живут только до конца запуска — меняйте файл коммитом.
- Не запускайте бота локально с тем же токеном одновременно с GitHub: Telegram отдаёт обновления только одному получателю.
- Модель работает на CPU, поэтому первый запуск с большим числом новых вакансий может занять десятки минут.
- В публичном репозитории логи запусков видны всем. В них попадают названия вакансий и вердикты модели, но не токен.
- GitHub отключает расписание, если в репозитории 60 дней не было активности.
